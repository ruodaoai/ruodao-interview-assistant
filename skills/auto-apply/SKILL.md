# 自动投递（Auto Apply）

面试助手第 6 页。目标是把「找岗位 → 定制材料 → 沟通/填网申 → 本人确认提交」串成可审计的流水线，而不是替用户做决定。

## 何时使用

- 用户要在招聘平台（Boss直聘 / 智联招聘 / 前程无忧）实时搜索岗位、按城市/关键词筛选。
- 用户要给 Boss 岗位发打招呼消息，或附带图片简历。
- 用户要把岗位加入投递看板、生成定制简历/求职信、自动填写企业官网网申表单。
- 用户要更新求职档案、答案库、安全规则。
- 不适用于：绕过登录/验证码/2FA、伪造经历、批量骚扰 HR、抓取需要登录的站内数据。

## 硬性边界（不可协商）

1. **绝不编造个人事实。** 材料与招呼语只允许重组简历与档案里已有的信息；缺失项写进 `warnings`，不要补。
2. **岗位信息只作参考。** 投递前必须提示用户在官方招聘页核对在招状态与薪资。
3. **登录、验证码、2FA、隐私协议、最终提交全部人工。** 招聘平台的登录/人机验证在可见浏览器里由本人完成；网申执行器遇到登录页最多等 120 秒，然后转为 `needs_user`。批量投递遇到验证会立即暂停，不会自行绕过。
4. **只有用户显式确认后才允许点击提交或发送招呼。** `requireConfirmation` 在存储层强制为 `true`；Boss 单条打招呼必须走确认弹窗。批量打招呼允许「一次确认、整批执行」，但确认弹窗必须列出全部岗位、频率与当日剩余额度；企业官网的「确认提交」仍然逐条确认，不能批量代点。
5. **没看到成功证据就不算发送成功。** Boss 打招呼需在页面看到消息记录或发送成功提示、且输入框已清空；网申没看到成功提示就停在 `needs_user`，由用户点「标记已投递」。
6. **不绕过反爬与风控。** 不注入 stealth、不伪造 UA、不并发轰炸；使用独立持久化浏览器上下文，用户可见。遇到验证就停下等本人处理。

## 工作流

1. **补齐档案**（`我的档案`）
   - 选择简历、填写姓名/电话/邮箱/城市/年限/学历，设置目标岗位、城市、办公方式、技能与答案库。
   - 档案缺关键项时页面会提示；不要替用户猜手机号或邮箱。
2. **挑岗位**（`岗位池`）
   - 若道岗位库：搜索/筛选来自 `GET /api/job-market/templates` 的真实公司岗位模板；或用「按档案推荐」走 `POST /api/job-market/recommend`（512 维本地哈希向量 `local-hash-512-v1`）。
   - 招聘平台：切到 Boss直聘 / 智联招聘 / 前程无忧，输入关键词与城市直接搜原站。关键词支持多个（逗号 / 顿号 / 分号 / 换行分隔，最多 6 个），会依次搜索、合并去重，并在结果里显示每个关键词的命中数量；「按档案全部岗位搜索」直接使用档案中的目标岗位。搜索会在客户端内置的可见 Electron 窗口（持久化分区 `persist:job-sites-<site>`）中进行；遇到登录或人机验证，请用户在窗口里完成，再点「我已处理，重新搜索」。
   - 平台结果按城市、屏蔽词、期望月薪、经验 / 学历、猎头、不活跃 HR、外包 / 驻场与挂岗时长规则过滤，有档案时本地打分排序；薪资不详或要求不明的岗位默认保留。外包识别覆盖标题、公司名、行业、标签与 JD 中的「外包 / 驻场 / 外派 / 派遣 / 外协 / 劳务 / 人力资源服务 / BPO」等字样，默认关闭，可在「安全规则 → 筛选与频率」开启。
   - 结果条上的 `已过滤 N 个` 可展开查看**逐条**被过滤的公司与岗位：类别（重复 / 城市不符 / 安全规则 / 疑似外包）、公司、岗位、城市、原因，并可当场「打开岗位页」或「加入看板」找回。用户问「为什么只剩这么几个」时，先解释这个拆解，再说明搜索量 = 关键词数 × 每页约 15 条。
   - 被过滤明细最多显示 12 条，点「显示更多」每次再展开 20 条；全部明细仍保留在本轮搜索结果里。
   - 一次搜索不是上限。结果区底部和「下一步」条都有 `继续加载第 N 页`（追加合并、已勾选岗位保留，Boss 最多 10 页），也可以换关键词或城市重新搜索；要向用户说明「想投更多就继续加载或换关键词」，而不是把当前条数当成总数。
   - Boss 列表页的薪资有字体混淆，公司名也常被匿名化（旧版本会显示成 `00-00K` / `未公开公司`）。现在旁路读取页面自己请求的 `joblist.json` 得到明文薪资、公司、城市、招聘者与在招状态；卡片上的 `核实招聘` 会再打开详情页读取 `detail.json`（`plugins:job-sites-verify`），补充招聘者活跃时间、岗位状态与完整 JD。
   - 每张平台岗位卡片显示 0–100 真实度分与「真实度较高 / 一般 / 偏低 / 建议先核实」，展开可见正面信号与风险信号。真实度是启发式提示，必须结合 `核实招聘` 与本人判断，不要向用户承诺岗位一定真实。
   - 挂岗时长（僵尸岗）判断有三个来源，取最大天数：① 平台自己显示的「发布于 / 更新于」（列表卡片与详情页都读）；② 本地 `userData/auto-apply/job-history.json` 记录的首次看到时间；③ 平台把发布时间往后改的次数。30 天起提示「挂出 N 天」，90 天以上不再判「真实度高」；平台反复改发布时间但本地连续看到的岗位会额外标「刷新过 N 次」。安全规则里可开启「过滤挂岗太久的岗位」并设置阈值（默认 90 天）。平台不展示发布时间的岗位只能靠本地首见，要向用户说明这一点，不要假装知道。
   - 专项外包公司可在岗位卡片上点「屏蔽公司」一键加入屏蔽名单；删除「安全规则 → 屏蔽名单」中的对应行并保存即可恢复。屏蔽词会匹配标题、公司名、行业、标签、职责与要求。
   - 每张卡片会显示公司情报：`疑似外包 X%` / `非外包` / `AI 未确定`、行业、公司性质（央企/国企/外企/上市/民营…）、该司在哪些招聘平台也在招、以及云端用户反馈数。判定顺序是本地规则 → 云端共享 → AI；`AI 未确定` 只代表模型无法确认，绝不能当成「非外包」。展开「判断依据」可以看到命中词与来源。
   - 结果条上的 `AI 判外包 · 本页还有 N 家待判` 打开判断弹窗：**只列还没判断过的公司**（本地规则、云端反馈、AI 结论或人工结论任一已判过的都跳过），默认勾选前 12 家，点「让 AI 判断选中的 N 家」才真正调用模型（约 3 路并发，结果缓存 14 天）；搜索时的自动标注仍只取 4 家，避免无谓消耗。
   - 判断弹窗与「记录与名单」页都能看到**已判定公司名单**，并支持人工纠正：`标为外包` / `标为非外包` / `撤销人工`。人工结论只写本机、优先于云端与 AI 结论（置信度 100），不会共享到云端；纠正后同一公司的所有岗位卡片立即更新。
   - 本页公司被判出疑似外包后，可勾选 `只看非外包（本页已标 N 家疑似）` 隐藏它们；这是视图筛选，不会删除岗位或写入屏蔽名单，取消勾选即可恢复。
   - 开启「过滤外包 / 驻场岗位」后，只有云端反馈或本地置信度 ≥ 70 的公司才会被隐藏，避免误杀正常公司。
   - Boss 岗位卡片左上角可勾选（最多 30 个），勾选后在工具条上出现「已选 N 个 · 预计 X 分钟 · 批量打招呼」，这是全自动投递的主入口。
   - 也可以手动添加真实岗位链接。加入看板时会被安全规则（最低匹配分、每日上限、屏蔽公司/关键词、外包过滤）拦截。
3. **生成材料**（看板 → `生成材料`）
   - 渲染层用当前简历模板生成 A4 HTML，主进程据此产出 PDF 与定制文案（headline / summary / coverLetter / highlights / answers）。
   - 有文本模型时用模型改写；没有模型时用本机模板兜底，结果一样受「不编造」约束。
   - 平台岗位若详情为空，会在该平台浏览器仍打开时自动读取岗位详情后再生成。
4. **沟通或填网申**
   - Boss 平台岗位：看板 → `打招呼`。安全规则里可选「AI 按简历生成」或「固定模板逐字发送」；固定模板支持 `{name} {job} {company} {city} {skills} {years} {degree}` 占位符。开启「允许重复沟通」后，同一岗位再次沟通会按顺序轮换配置好的重复沟通话术；留空则生成一条简短的再次沟通消息。弹窗内可编辑、重新生成（AI / 用模板），确认后发送；可勾选附带图片简历。每日打招呼数量受 `dailyLimit` 约束（每个招聘网站独立计数，默认 10）。只有页面出现消息记录/成功提示且输入框清空才记为已投递。
   - Boss 批量：岗位池勾选 → `批量打招呼` → 确认弹窗（列出岗位、频率、当日剩余额度、免责勾选）→ 一次确认后顺序执行。队列支持 `暂停 / 继续 / 停止`；顶部进度卡会显示每一条的结果（已发送 / 需本人处理 / 跳过 / 失败）与原因。遇到登录、验证码或未确认发送时整批自动暂停，处理完点「继续」即可。
   - 批量不会重复投递：已投递（或已标记已投递）的岗位、同一职位链接/职位 ID、冷却期内的公司、回复过「不合适」或已屏蔽的公司都会被跳过并写明原因。
   - 智联 / 前程无忧：岗位池卡片 → `投递简历`（看板里同一岗位也可直接点），确认弹窗里可选「用平台在线简历投递」或「附上我的简历文件」。执行器会打开详情页点「立即投递 / 立即申请 / 立即申请该职位」→ 处理确认弹窗（可能是「选择简历 → 确认投递」两步）→ 只有页面出现「投递成功 / 已投递」才记为已投递，否则计入「需本人确认」。平台要求登录或人机验证时立即停下，等本人处理。
   - 这三个平台也能进批量队列（与 Boss 共用防封节奏、每日上限、公司冷却与台账）：Boss 走打招呼，其余走详情页直投。前程无忧若已在平台勾选「30 天快速投递」，页面会直接提交、不再弹确认页，执行器对其成功提示同样做校验。
   - 企业官网岗位：看板 → `自动填写`。独立有头浏览器打开官方招聘页，按字段语义填写姓名、电话、邮箱、城市、年限、学历、链接、自我介绍、答案库；每一步写证据：截图、日志、已填字段、最终 URL 与页面标题。
5. **人工确认提交**（看板 → `确认提交`，仅企业官网岗位）
   - 弹窗展示将要提交的岗位与材料摘要，必须勾选确认后才会点击提交。
   - 遇到登录/验证码/隐私协议会暂停并提示本人处理；处理完可继续。
6. **收尾**
   - `标记已投递`：用户确认页面出现成功提示后手动标记，写入 `submittedAt`。
   - `证据截图`：查看本次投递/打招呼的截图与执行日志。
   - `关闭窗口`：结束企业官网网申的浏览器会话，证据保留在本机；招聘平台窗口在岗位池状态条里关闭，登录态保留。

## 批量投递与防封节奏

批量队列只是把单条打招呼串起来，真正的发送仍走同一条单条流程（生成招呼语 → 确认授权范围内发送 → 截图证据 → 校验成功）。防封参数在「安全规则 → 防封节奏（批量投递）」：

- **投递时段**：默认 `09:00-21:00`，窗口外自动等待，不会半夜发消息。
- **随机间隔**：默认 45–150 秒，逐条随机；不会固定节奏。
- **每日上限**：每个招聘网站独立计数，`dailyLimit` 控制每个网站每天最多投递的岗位数；`dailyCompanyLimit` 同时限制每个网站每天投递的不同公司数（默认 20）。公司冷却、屏蔽和外包结论跨网站共享；某个网站额度用完只跳过该网站剩下的岗位，不影响其他网站。
- **公司冷却**：同一家公司默认 30 天内不再重复打招呼。
- **浏览器窗口**：`showBrowserWindow` 默认开启，批量投递时显示平台窗口（不抢键盘焦点），方便看过程；遇到登录或人机验证会自动把窗口放到最前，可直接扫码。关闭后完全后台运行。
- **连续失败熔断**：连续 3 次未确认成功（登录失效、页面异常）会暂停队列，要求人工检查。
- **验证冷却**：出现验证码/风控提示后进入 30 分钟冷却，期间不再自动发送。

## 投递结果台账

看板与岗位池共用一份结果台账（`userData/auto-apply/outcomes.json`）：

- 记录 `applied`（已投递）、`interview`（已面试）、`rejected`（被拒 / 回复不合适）、`blocked`（屏蔽公司）。看板「已投递」记录上有 `已面试` 与 `回复不合适` 两个按钮。
- 回复「不合适」会自动写入公司冷却/跳过原因；开启「自动拉黑拒信公司」时同时加入屏蔽名单，并在云端以匿名统计上报。
- 台账用于：批量前的重复投递检查、AI 教练的今日数据、公司情报里的 `applied/interview/rejected` 计数。

## 记录与名单（第 3 个页签）

「记录与名单」把散在各处的本机记录集中展示，搜索框可按公司 / 岗位 / 人事姓名过滤：

- **已经打过招呼的岗位**：来自投递台账，逐条显示公司、岗位、招聘者（人事）、来源平台（Boss直聘 / 猎聘 / 智联 / 前程无忧）、结果（已投递 / 已面试 / 回复不合适）、时间与备注，可回到岗位页，也可「加入看板」。顶部统计记录数、公司数与人事数。
- **已屏蔽的公司**：即安全规则里的屏蔽名单；每行「恢复，不再屏蔽」立即生效，该公司岗位会重新出现在搜索结果里，已打的招呼记录不受影响。
- **已判定外包的公司**：复用已判定公司列表，支持搜索与人工改判（写本机，优先于自动结论）。
- 「刷新台账」重新读取结果台账与公司判定名单；屏蔽、改判等操作即时写盘，不会重复投递同一岗位 / 公司。

## AI 求职教练

页面上方的教练卡展示今日已投、今日面试、今日不合适、本周与累计数量，以及今天投递过的公司。点「分析今天投递」会调用 `plugins:auto-apply-coach`：

- 有模型时把档案、规则、今日/本周统计、最近记录与公司情报摘要交给模型，输出 `headline / focus / actions / risks`（严格 JSON）；没有模型或调用失败时用本地规则给出同样结构的建议。
- 建议只基于台账与档案事实，不编造面试结果或公司评价；风险项会提醒权益、薪资口径与投递节奏。

## 求职小助手

页签栏右侧的「求职小助手」是对话式配置入口，面向「不知道该填什么 / 想一次配好多岗位」的用户。

- 输入自然语言诉求，例如「我想找 Java 和 AI Agent 开发工程师，深圳，期望 25-40K，帮我配好并搜索」或「外包和驻场岗位都不想投」。
- 助手读取脱敏后的档案（不含手机号、邮箱、微信、个人链接）、安全规则（Webhook 只显示为「已配置」）、简历正文（截断）、平台登录状态与最近看板记录。
- 输出：`reply`（解释与建议）、`profilePatch`（目标岗位 / 城市 / 技能 / 年限 / 学历 / 薪资 / 简介 / 办公方式）、`rulesPatch`（招呼语方式与模板、重复话术、薪资与频率、过滤开关、屏蔽名单）、`searchPlan`（平台 + 关键词 + 城市）、`questions`（缺失信息）与 `warnings`。
- 白名单限制：补丁不能修改 `requireConfirmation`，不能写入 Webhook，不能绕过登录 / 验证码；搜索计划最多 4 个平台、6 个关键词。
- 所有补丁只在用户点击「应用配置 / 应用并搜索」后保存；搜索通过既有平台窗口执行，遇到登录或验证会停下并提示本人处理。
- 无模型时走本地规则：检查目标岗位 / 城市 / 简历 / 期望薪资、建议开启不活跃 HR 过滤、识别「外包 / 驻场」诉求并建议开启外包过滤、生成可编辑的固定模板，并按档案目标岗位给出搜索计划。

## 数据与存储

- 投递档案、规则、看板：`userData/auto-apply/state.json`（原子写入，损坏自动备份；最多 200 条记录，状态 ≤ 24 MB，单份 HTML ≤ 4 MB）。
- 公司情报缓存：`userData/auto-apply/company-intel.json`（最多 3000 家；云端结果缓存 6 小时，AI 结论缓存 14 天）。
- 投递结果台账：`userData/auto-apply/outcomes.json`（最多 5000 条，只存结果，不存简历内容）。
- 证据：`userData/auto-apply/evidence/<applicationId>/`，只对该条记录开放读取。
- 岗位标签：`userData/auto-apply/job-tags.json`（最多 3000 个岗位，同一岗位最多 8 个标签、单个标签 ≤ 20 字）；打了标签的岗位批量投递 / 批量打招呼时跳过。
- 备份：导出为单个 JSON（上限 64 MB），覆盖档案、规则、看板、`outcomes`、`job-tags`、`company-intel`、简历库、面试场次与插件设置；自动快照写在 `userData/interview-data-backups/`，每天首次启动一份、保留最近 5 份。录音、证据截图、登录态与批量进度不进备份。恢复按合并处理，不删除当前数据；恢复 token 只对应本次经对话框选中的文件或白名单内的快照名，不接受任意路径。
- 招聘平台登录态：Electron 持久化分区 `persist:job-sites-<site>`（落盘于 `userData/Partitions/`），每个平台独立、只留在本机；插件不读取 Cookie 内容。
- 简历仍由简历库统一管理，自动投递只引用 `resumeId`，不复制用户简历文件。
- 云端共享只上传：公司名/归一化键、外包判定与置信度、行业、性质、招聘平台、结果计数与匿名上报者 ID（登录用户为 `u:<id>`，未登录为本机随机 ID，落盘于 `userData/device-id.json`）。不上传简历、联系方式、聊天内容或 Cookie。

## IPC 契约（渲染层 → 主进程）

`plugins:auto-apply-state / -profile-save / -rules-save / -companies / -catalog / -recommend / -add / -update / -remove / -prepare / -attach-html / -run / -mark-submitted / -close / -evidence`

招聘平台：`plugins:job-sites-status / -open / -close / -search / -verify`、`plugins:auto-apply-greeting / -greet`、`plugins:auto-apply-assistant`

批量与台账：`plugins:auto-apply-batch-start / -batch-status / -batch-pause / -batch-resume / -batch-stop`、`plugins:auto-apply-outcomes / -outcome-report`

岗位标签：`plugins:auto-apply-job-tags`（列出本机已打标签的岗位）、`plugins:auto-apply-job-tags-save`（`{ job?, key?, tags? }`，`tags` 归一化去重、限 8 个 × 20 字；传空数组即清除该岗位标签）

数据与备份：`interview-data:status`（各类数据数量与自动快照列表）、`interview-data:export`（弹保存框写出备份 JSON）、`interview-data:pick-restore`（选文件并返回预览 + token）、`interview-data:restore`（按 token 合并导入）、`interview-data:restore-snapshot`（按白名单快照名恢复）、`interview-data:open-folder`。恢复前必须由本人在界面上确认，模型不得代调 `restore`。

公司情报与教练：`plugins:auto-apply-company-intel / -analyze-companies / -company-verdicts / -correct-company`、`plugins:auto-apply-coach`

`-analyze-companies` 接收当前结果里的 `jobs` 与 `limit`（默认 12，最大 20），按公司去重后返回 `companies / pending / outsourced / clean / uncertain / remaining / aiAvailable / items[]`；已判定的公司（人工 / AI / 云端 ≥2 条 / 本地规则命中）不会进入 `pending`，也不会再送模型。渲染层用 `items[].intel` 回填同一公司的所有岗位卡片，并提示「还有 N 家待判」。`AI 未确定` 不计入 `clean`。

`-company-verdicts`（`limit` 默认 500）返回本机已判定公司名单（含人工纠正），供判断弹窗与记录页展示；`-correct-company` 接收 `{ company, verdict: "outsource" | "not_outsource" | "", note? }`，空 verdict 表示撤销人工结论。人工结论只写本机 `company-intel.json`，不共享到云端。

状态机：`planned → prepared → filled → needs_user → submitted | skipped | blocked | failed`；批量队列另有 `running | paused | stopped | done`，单条状态 `queued | running | sent | needs_user | skipped | failed`。

## 验收

- `cd product/ruodao-desktop && npm run build:electron && npm run build:vite && npm run check:ipc`
- `npm run verify:interview-workbench`：工作台必须为 10 页且第 6 页标题是「自动投递」。
- `npm run test:job-sites`：城市码、薪资/经验/学历解析与过滤、多关键词、招呼语模板与重复沟通、规则归一化、助手本地模式、Boss 列表/详情接口映射、混淆薪资抑制、真实度评分与长期在招。
- `npm run verify:job-sites-pool` 或 `node scripts/e2e/verify-job-sites-pool.mjs`：多岗位搜索入口、招呼话术配置保存与模板渲染、记录与名单页（屏蔽名单恢复、打招呼记录里的人事与平台、已判定公司人工改判）、求职小助手、平台岗位看板动作与响应式布局。真实搜索结果态（过滤原因展开、AI 判外包条、下一步引导、继续加载）需要登录 Boss，日常由 `test:auto-apply` 的 `composeCompanyIntel` 单测与 SSR + Electron offscreen 截图校验覆盖。
- `npm run verify:company-judge`：用 Vite SSR 渲染 AI 判外包弹窗与记录页（假数据 6 家公司：3 家待判 / 3 家已判），断言只列待判公司、已判公司的来源与人工纠正按钮、打招呼记录与屏蔽名单；再用 Electron offscreen 在 1180 / 760 宽度截图到 `.e2e-artifacts/company-judge/`。
- `node scripts/e2e/verify-job-sites-window.mjs`：真实 Electron 窗口稳定性（Boss 首页不 about:blank 循环、`navigator.webdriver=false`、有登录入口、可关闭）；设置 `E2E_LIVE_SEARCH=1` 会额外跑一次前程无忧多关键词真实搜索（默认关闭，避免日常触发平台风控）。
- `npm run test:auto-apply`：匹配、规则拦截、材料不编造、状态机；另覆盖防封窗口/间隔/上限/熔断、公司名归一化与外包本地判定、`AI 未确定 ≠ 非外包`、云端多人反馈优先、投递台账聚合、批量队列的跳过/暂停/停止/失败隔离。
- 后端：`cd ruodao-backend && ./mvnw -q -Dtest=CompanyNameKeyTest test`，锁定两端公司名归一化规则一致。
